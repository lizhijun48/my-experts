# 高项论文评分 Skill

## 何时使用
- 用户贴出一篇「信息系统项目管理师（高项）」论文，要求打分/批改/预测能否过。
- 用户在做软考高项备考，需要把一篇练笔快速定位薄弱项。
- 为「智题宝」小程序或训练营批量产出论文评分报告（本 Skill 即其内核）。

## 评分框架（官方口径，满分 75 / 合格 45）
权重按历年阅卷口径折算到 75 分制：切合题意 30% / 应用深度 20% / 实践性 20% / 表达能力 15% / 综合能力 15%。
| 评分项 | 满分(分) | 考察点 |
|---|---|---|
| 切合题意 | 23 | 紧扣论题、覆盖全部子题目（漏答即大幅扣此项 30%+） |
| 应用深度与水平 | 15 | 十大绩效域/理论与项目实际结合的紧密度 |
| 实践性 | 15 | 项目真实可信（角色/周期/金额/成果等具体细节） |
| 表达能力 | 11 | 结构清晰、逻辑连贯、文字通顺、无语病 |
| 综合能力与分析 | 11 | 总结反思、独到见解、风险/问题解决深度 |
| **合计** | **75** | 合格线 45 |

> 2023 下半年起改为「绩效域（Performance Domains）」考法，论文常要求结合 8 大绩效域：
> 利益相关者 / 团队 / 开发方法和生命周期 / 规划 / 项目工作 / 交付 / 度量 / 不确定性。
> 摘要不再单独设分但仍须有（200–300 字），无摘要印象分差、易被判切题不足。

## 执行流程（agent 照做）
1. 调用 `references/score_essay.py` 做**机械检查**：字数、是否有摘要、段落结构、8 大绩效域命中数。
   ```bash
   python references/score_essay.py <论文文件路径>
   # 或管道： cat essay.md | python references/score_essay.py
   ```
2. 结合 `references/rubric.md` 的逐维细则，由 agent 做**定性评判**，给每项打分（在权重区间内）。
3. 输出结构化报告（见表「输出模板」），必须含：总分(预测合格线45)、分项分、Top3 扣分项、3 条可落地修改建议、乐观/保守两档预测。
4. 语气：像严苛但负责的阅卷老师——直接点出硬伤，不客套。

## 边界
- 本 Skill 给的是「练习向」预测，非官方阅卷结果；正式考试以阅卷组为准。
- 不代写论文（合规红线），只批改与建议。
