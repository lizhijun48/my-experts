# 上架价值判定与 H1/H2/H3 验收（来源：§一之二）

> 本文件由源资产原文程序化提取，保持原样以零信息丢失；口径以原文为准。


## 一之二、价值判定：上架标准与硬闸门（官方口径，先于一切设计）


> **本节优先于第三节的四步流程**：先判断"这个技能值不值得存在"，再谈怎么写。用户提出做一个技能时，**先过本节，不合格就直接说不合格并给出改造方向**，不要顺着把不成立的技能设计完。

### 1. 官方四维核心标准

| 维度 | 含义 | 反面（即不合格） |
| --- | --- | --- |
| **高复用** | 解决一类反复出现的真实问题 | 一次性、个性化咨询（如纯个人心得、私人经验集） |
| **可交付** | 输出是可直接使用的成果（文档/PPT/表格/报告/清单/脚本/代码/网页/图表） | 只给"分析建议"不给出成品 |
| **有标准** | 输入要求清晰、输出结构稳定、口径与边界明确 | 依赖用户临场提问、每次口径漂移 |
| **可迭代** | 可通过版本更新持续增强（新增模板、案例、检查项、能力模块） | 一次性做完无法演进 |

**快速自测法**：若该方法论能在固定输入下稳定产出"可直接使用"的结果，且在该场景下的效果与确定性**明显优于通用大模型**，它就适合做成 Skill。

### 2. 总闸门：必须明显优于裸用通用大模型（不满足即判定为"简单包装"）

- 技能必须在特定场景通过**结构化流程、标准模板、校验机制或领域规则约束**，实现效果/稳定性/效率上明确优于裸问通用大模型，形成**可感知、可对比**的独特价值。
- 反面：一个"写文案"技能输出质量与直接问大模型没区别，没针对场景做 prompt 优化与模板匹配 → **对用户没有任何使用价值**。
- **这意味着：仅靠"写得更全的提示词"不足以成立。** 要把差异升级为模型在结构上做不到的事：
  - `scripts/` 的**确定性校验/计算**（概率式生成永远做不到，最有说服力）；
  - `references/` 的**领域原文/规则库/模板库**（解决模型凭记忆会漂、会误引、会编造）；
  - 多阶段固定工作流（模型天然会漂移）。

### 3. 付费技能的额外标准（若用户要做付费）

增量价值须至少满足其一：① 明确的外部成本（第三方 API/数据库/算力）；② 明显专业性与稀缺性，与免费方案有可感知差异；③ 创新性或技术壁垒（专有数据/方法/模型）。

**一票否决项**：核心功能有明显 Bug、描述虚假夸大、**简单 API 套壳无附加价值**、隐私或安全风险、违规内容。

### 4. 蓝海选题口径（找方向时必用）

- 正确问法不是"哪个领域没人做"，而是「**哪群人每天在重复填表/写记录，却没人帮他们**」。优先找：高频重复（日/周/月循环）× 强合规强制 × 主体基数大 × 无持证资质门槛 × 可锚定公开法规/标准。
- **供给密度必须用真实检索数字，且每个方向配交叉验证词**：
  - 警惕**假阴**（主词命中 0，但能力藏在某个全能工具里，例："表格合并"=0 却被 `excel-processing` 覆盖）；
  - 警惕**假阳**（命中数很高但全是无关子串，例："安全"89 全是 IT/校园安全）。
- 已确认的红海不必再投入：报销、对账/核对、合同、财税全税种、周报/会议纪要、教案备课、各类评语、Excel 通用处理、PPT/PDF/视频。
- 已确认的空白方向类型：**传统实体行业的一线合规台账**（如食品安全台账、消防巡查记录、安全生产文书）。

### 5. 验收硬流程：三段式（H1 → H2 → H3），A/B 只是最后一关

新资产（或大改版）的验收是**三段式，顺序不可颠倒**：

| 段 | 做什么 | 不达标的后果 |
| --- | --- | --- |
| **H1 · 覆盖度矩阵** | 把技能要处理的输入空间分解为**有限维度**（阶段 × 请求类型 × 信息完备度 × 输入性质 × 数字来源 × 多轮），逐格确认有规则兜住 | 覆盖有空格 = 该场景临场发挥、换模型就漂 |
| **H2 · 格式与契约** | 模板**列名 ↔ 脚本解析列名逐字对齐**；输入要求、输出结构、口径边界写死 | 契约不一致 = 假 ERROR / 假通过 |
| **H3 · A/B 增益 ≥20%** | 见下表 | <20% = 与裸用大模型无实质差异 → 简单包装，不得上架 |

> ⚠️ **跳过 H1 / H2 直接做 H3，就退化成"绝对质量自证"**——"题全过"只证明不装技能也还不错。

**H3（A/B 对照）的做法**：

> **这是最容易犯的方法论错误**：跑 20 题全过，只证明了"装上技能后输出不错"，**没有证明"比不装技能更好"**。

| 组 | 处理 |
| --- | --- |
| A 组 | system persona = 该 SKILL.md |
| B 组 | **无任何 system**，只有 user 提问（模拟用户直接问通用大模型） |

同题、同模型、同 rubric。**硬性判定**：相对增益 **<20%** 即判定为"与裸用大模型无实质差异 → 简单包装"，应**回炉加固或放弃，不得上架**。

**口径（缺了它就是「数字没带口径」）**：分母 = B 组（无 system）同题同 rubric 得分；分子 = A 组得分 − B 组得分；相对增益 = 分子 ÷ 分母。三项各自量化——反编造 / 越界拒绝 / 结构一致性各记 **0 / 部分 / 显著**——**合成判定取最弱一项为主、另两项佐证**：任一项为 0 且另两项无「显著」即不达标。三项记录与合成结论都要写进报告。**执行方式**：作者人工抽样跑，不派 agent 脚本化跑模型 API（费用高、慢、易抖动，见 skill-dev-standard Step 4）。

**两线优先级（缺了它，这道「不得上架」的硬闸门结论不可判定）**：**先过数字线，再过合成线，两线全过才达标**。数字线不过 = 直接不达标（不必再看三项）；数字线过、但合成线任一项为 0 且另两项无「显著」= **一票否决**，仍不达标。**两套记分的对应**：「得分」是 rubric 量化值，「0 / 部分 / 显著」是其归档档位——**显著** = 该项明确优于 B 组且有用例证据；**部分** = 有优势但不稳定或证据弱；**0** = 无优势或 B 组更优（须如实记录，不得隐去对结论不利的证据）。

增益通常集中在三处（应逐项量化）：① 反编造（是否把占位符填成"像真的"数据、是否把未完成项默认写成"已完成"）；② 越界拒绝（是否顺从伪造/规避/越权请求）；③ 结构一致性（多次调用口径是否稳定）。

**诚实记录义务**：若裸模型在内容详尽度上反而更优，必须如实写入报告，不得隐去对结论不利的证据。
