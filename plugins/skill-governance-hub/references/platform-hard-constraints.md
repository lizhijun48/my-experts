## 一之三、平台硬约束速查（以实测为准，不臆造平台逻辑）


下表是本项目**实测确认过**的平台校验约束。回答「为什么会被拒、怎么改」时以此为准，**不要臆造平台的判定逻辑**。

| 平台校验约束 | 真实根因 | 判据 |
| --- | --- | --- |
| **目录层级超限** | 包内文件相对包根超过 1 层（`examples/`、`test/` 下再嵌套） | S7（技能包）/ G9b（专家包内嵌技能）/ **G9c（专家包根 `references`/`scripts`/`templates`/`examples`）** |
| 解析失败 | `tags` 不是**恰好 3 个**；或缺少 `.codebuddy-plugin/plugin.json` | G2/G3 / Z1 |
| 解析失败 | **文件名不安全**：含连续点 `..`、主名以点或空格结尾、含非法字符 `: * ? " < > | \`、或为系统保留名（CON/PRN/AUX/NUL/COM1-9/LPT1-9） | **F12** |
| 解析失败 | `displayDescription.zh` 超 100 字；`defaultInitPrompt` 与 `quickPrompts[0]` **未逐字一致** | G12 / G13 |
| 解析失败 | **专家名称含空格或特殊字符**：付费资产的名称仅支持**中英文、数字和"-""—**——实证「Altium 排错专家」因 1 个空格被拦、「扣子（Coze）系统教程专家」的全角括号同属违例（免费在售包含空格照过审，规则仅针对付费资产） | **G15** |
| 解析失败 | **专家名称超长**：`displayName.zh` 超 **15 字**（平台按字符数计，**英文字母逐个算 1 字**）——实证「Altium Designer 排错专家」20 字被驳；英文名不受此限（en 24 字符已过审） | **G14** |
| `yaml: line N: mapping values are not allowed in this context` | 值含冒号（尤其**全角冒号后紧跟 ASCII 字母**）且未加双引号 | S4 |
| `yaml: line N: did not find expected key` | **frontmatter 结构损坏**：一个键的值里混进了**字面量换行**（如脚本 heredoc 把 `\n` 写成两个字符 `/n`，产出 `profession:/n  en: "X"`） | 见下方「结构损坏类」 |
| **运行期表现不达预期** | SKILL.md 由大段空表格构成，诱导模型输出整表占位 | **无静态判据**，必须走行为层压测（关 3） |
| 脚本不生效 | 有 `scripts/` 但未声明 `allowed-tools`，或声明了未放行执行权限 | P3 |

**两条最关键的教训**（都来自真实翻车）：

1. **「本地体检 PASS」≠「平台能上传」**。目录层级超限与 YAML 冒号这两类问题，本地文件系统与 PyYAML 都**不会报错**，只有平台会拒——所以提交前**必须跑 upload 闸门**，这一步不能靠"我觉得没问题"。
2. **模板越"齐全"，越容易把模型锁死在占位符里**。真实发生过一次「43 行空表 + 28 个占位格 + 14 处待补充」的翻车：**看起来很规范，但什么也没干**。自检/分析类技能的输出模板必须**条件化**：用户给了信息就必须给出实质判断，**明令禁止整表占位**。
3. **「本地能落盘」同样 ≠ 「平台能解析」**（2026-10-12 实证）。一个文件名叫 `…-找到PADS自带的图标文件powerpcb..md`（**连续点 `..` + 主名以点结尾**，源自案例原标题以句点收尾），在 Windows NTFS 上 `os.open` 创建成功、`zipfile` 读写畅通、上传闸门当时也没有对应判据——**平台开包即报「解析失败」并逐字点名该文件**，整个包传不上去。修掉后同包一次通过。凡涉及"平台会怎么处理这个名字/这个路径"的，别用"我本地试过没问题"下结论。

### 平台开包前的最后一道自检：模拟解析测试（2026-10-13 固化）

静态闸门之外，上传前再跑一遍**平台视角模拟解析**，比任何单条判据都接近真实路径：

| 层 | 做什么 | 抓过什么真问题 |
| --- | --- | --- |
| ① 落盘 | 把 zip 逐条目**真实写到磁盘**（`open(p,"wb")`），再回读比对字节 | 证明包可完整解包、无损坏条目 |
| ② 路径 | 扫 `..`／绝对路径／盘符开头；核对顶层形态与目录深度 | 抓到过 `powerpcb..md`；确认单专家=裸根、专家团=带顶层 |
| ③ 编码 | 非 ASCII 条目**必须置 UTF-8 标志位**（否则平台按 cp437 解出乱码名） | 481 个中文名逐一核对（范围：pads-troubleshoot 包 references 下全部案例文件名） |
| ④ 元数据 | 用**标准 JSON/YAML 解析器**读 `plugin.json` 与 `agents/*.md`，逐项校验必填字段、tags 数、版本三处一致、头像尺寸 | 曾靠它发现"`plugin.json` 在根"是错假设（实际在 `.codebuddy-plugin/`，与在售单专家一致） |
| ⑤ 内容 | 逐个读正文：可解码、非空、有标题结构 | 481/481 通过（范围同上：pads 包全部案例正文） |

要点：**每一层都要有"该失败"的负向样本**（拿一个已知坏包跑，必须看到它红）。只跑正向等于没测——本轮就是靠负向样本证明了测试器不是又一次假通过。

### YAML 两类报错，修法完全不同（不要混为一谈）

| 报错原文 | 真因 | 修法 |
| --- | --- | --- |
| `mapping values are not allowed in this context` | 值含冒号（尤其全角冒号后紧跟 ASCII 字母）且未加引号 | 给该值**整体加双引号** |
| `did not find expected key` | **结构损坏**：值里混进字面量换行或多余键（如 `profession:/n  en: "X"`，`/n` 是写坏的字面量 `\n`） | 修**换行符本身**（把 `/n` 还原成真换行），**不是加引号** |

⚠️ **只写一类会误判**：遇到结构损坏类却按"冒号问题"去加引号，改了也不生效（本类问题曾真实绕了一整轮）。**本地 PyYAML 不会报这两类错，只有平台 Go-YAML 会**，所以不能靠"本地看着没问题"。

### 平台解析严格度按「文件角色」不同（实测，反直觉）

| 角色 | 严格度 | 证据 |
| --- | --- | --- |
| 团队成员 `agents/*.md` | **严格** | 两次实测驳回 |
| 独立技能包 `SKILL.md` | **严格** | 09-09 实测驳回 |
| 单专家 `agents/*.md` | **容忍** | 在售包中 `description: … (BLM): gap …` 经 PyYAML 判无效，却成功上架 |
| 专家包内嵌 `SKILL.md` | **容忍** | 同上 |

**用途**：不区分角色，就会把**已上架在售**的资产判成缺陷、逼用户去改 → 违反下方「资产冻结纪律」。正确做法是**按角色分流严重度**（团队 / 独立技能 = FAIL；单专家 / 内嵌 = WARN，不判错）。

### 本地关口清单（`audit.py --profile upload` 是唯一提交闸门）

| 关口 | 分发状态 | 作用 | 退出码口径 |
| --- | --- | --- | --- |
| `audit.py --profile upload` | ✅ **随包分发**（本包 `skills/skill-quality-audit/scripts/`） | 结构硬闸门（含 S7 / G9b 目录层级、G12/G13 等） | **0 = 通过 / 1 = 命中必修项 / 2 = 用法或环境错误**（2 不得当"未通过"报） |
| `preupload_gate.py` | ⚠️ **作者工位配套，不随包分发** | 前置字段核查 **9 项**：CATEGORY / EXPTYPE / PLUGINREQ / AGENTDESC / YAMLSTRUCT / CONTRACT / VERSION / REFS / AUDIT | **0 = 可传 / 1 = 先修 / 2 = 环境错「或 0 对象」**（路径没扫到也返回 2） |
| `yaml_precheck.py` | ⚠️ **作者工位配套，不随包分发** | 真 YAML 解析器（PyYAML）独立裁决，目录 / zip 通吃 | **0 = 通过 / 1 = 有文件解析失败 / 2 = 用法或依赖缺失**（以其 `--help` 为准） |

**三条硬约束**：

1. **只有 `audit.py` 随包分发**——"只装了 WorkBuddy"的环境里，能且只能跑它；另外两个是作者工位工具，**不假定存在**，也不当作"提交前必跑"。
2. **工具缺失时的降级（必写，不许假装跑过）**：`preupload_gate.py` / `yaml_precheck.py` 不在，就**明说"该步未执行"**，改用 `audit.py --profile upload` 的退出码 + 人工按 9 项清单核对字段，并在结论里标注"未做真解析器裁决"。**不得用"我觉得没问题"顶替退出码，也不得把未执行的工具写成 PASS。**
3. **三套 0/1/2 语义各不相同，禁止跨工具套用**：尤其 `2`——`audit.py` 的 2 是用法/环境错误，`preupload_gate.py` 的 2 还含「0 对象（路径给错，一个包都没扫到）」，`yaml_precheck.py` 的 2 是用法或依赖缺失。**套错会把"没扫到"读成"通过"，或把"依赖缺失"读成"未通过"。**

**优先级不变**：`audit.py --profile upload` 是**唯一提交闸门**（关2 跑的就是它）；另两个只用于定位，不替代闸门结论。

⚠️ **`audit.py --profile upload` PASS ≠ 平台能过**：**平台校验项是本地判据库的超集**。凡拿到新的驳回原文，**当天**补判据 + 负向夹具，否则同类问题下次照旧逃逸。
