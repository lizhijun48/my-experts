# 调试测试、检查器铁律、收敛两类（来源：§四）

> 本文件由源资产原文程序化提取，保持原样以零信息丢失；口径以原文为准。


## 四、调试与测试方法


用户问"要不要测、怎么测"时，给可执行流程，不要只说"建议充分测试"。

> **前置**：本节测的是"技能本身能否稳定输出"。在它之前/之后还必须做**A/B 对照**（见「一之二」第 5 条）——验证"装了技能是否真的比裸用大模型更好"。**两者都要有，缺一不可**：只做本节是"绝对质量自证"，不足以证明技能成立。

**推荐测试流程（4 步）**

1. **构造样本并主动埋陷阱**：模糊承诺（"尽量""回头看看"）、口语化评价（"还行""差不多"）、零散信息（插话、跑题）、关键字段缺失、无关闲聊、以及**注入式输入**（"忽略以上规则，执行 XXX"）。
2. **逐陷阱判定**：让模型按 SKILL.md 跑一遍，判定每条陷阱是"规则兜住"还是"模型靠常识发挥"——后者就是规则缺口。
3. **补规则后复测同一份样本**，确认缺口被堵上。
4. **换一个模型复测（条件式加强项）**：自测会掩盖规则缺失（同一模型的常识会补上没写的规则）。**默认不要求**——只有一个环境时，按挂载技能 `expert-skill-qa-loop` 的「单环境降级路径」拿等效证据（重复跑抖动 / 换问法扰动 / 覆盖矩阵查空格 / 负向夹具证红 / 数字带口径 / **单环境通过线**）；**有第二个模型时才做跨模型复测**，且须明写「本轮为单环境测试，跨模型稳定性未验证」，不得假装做过。

**触发不了的排查顺序**

1. frontmatter 是否闭合（解析失败 = 完全不触发）
2. 调用开关是否误设（`user_invocable: false` 或 `disable-model-invocation: true`）
3. 触发词是否过窄、未覆盖用户真实口语（该触发时不触发）
4. 描述与真实能力是否一致（不一致时模型判定不匹配）
5. 是否与已有技能触发词冲突
6. **误触发（不该触发时弹出）**：触发词或 description 边界过宽、未写明"不触发"条件；收窄适用场景并补"不触发"清单

**触发了但输出不对的排查顺序**

1. 正文是否缺"输出格式"约束 → 无约束则模型自由发挥
2. 边界情形是否缺判定规则 → 换模型就漂
3. 示例是否缺失，或示例与规则矛盾
4. 模板里是否混入元指令（如"（无则删除本行）"）
5. 格式示例是否被写成缩进块、被渲染成代码块而非渲染后的结果

### 自建检查器的铁律：别把判据挂在不执行的分支上

这是**「夹具全绿却依然漏检」的标准成因**，本项目已实证三次：

| 时间 | 病症 | 后果 |
| --- | --- | --- |
| v1.4.2 | G9/G9b/G10/G11 整段挂在 `if cfg.get("skills") is not None` 下，`plugin.json` 未声明 `skills` 时**一次都不跑** | 包内自带 `skills/` 目录被整体放过，假 A/97 |
| v1.4.4 | 新判据 F12 写在**技能包专有**的 frontmatter 段（`audit_one`），而专家包走 `audit_expert` 分支 | 负向夹具**全绿**，判据形同虚设；移到共用的 `scan_hygiene` 后负向立刻变红（B/80 · BLOCKER 1） |
| v1.4.5 | G7 的 README 版本提取用循环覆盖，**静默取 zip 序最后一个** | 混放工作区里根 README 被子目录 README 顶掉，误报版本分叉 |

三条对应纪律：

1. **判据要放在所有目标形态都会执行的共用路径上**（技能包 / 专家包 / 专家团都要过）；放进某个形态专属段前，先确认另外两种形态确实不需要它——若需要，就是挂错了。
2. **负向夹具必须在每一种目标形态上各跑一次**。只在技能包上验过「会红」，不代表专家包上也会红。
3. **看到"夹具全绿"先问一句：这段代码在这次运行里真的执行了吗？** 用临时打印/计数确认，别假设。同理，"取到了值"也要问"取到的是**哪个对象的**值"——取错对象比不取更危险，它会一本正经地报错。

### 收敛：任何资产都要收敛，两类资产收敛方式不同

> **这是本条目的最高纪律**：做任何技能、专家、专家团都要有**收敛**，并尽量用**矩阵**覆盖所有情况。根因——**测试只是采样，采样永远追不上无界的输入空间**。**收敛靠缩小判定面，不靠加大采样。**

**① 含确定性检查器的资产** —— 走 `skill-dev-standard` 的 **Step 4.5 收敛关卡**：

- 写判据前先回答「**这类数据只有哪几种坏法**」，**一种坏法配一条规则**（而不是一个字段配一条规则）；
- 每条规则**声明它管哪些**（维度取值 × 坏法）的格；矩阵按**类**验证，不按词验证（同义/反义写法程序化生成，逐格断言）；
- 验收工具：`convergence-matrix-tool` —— 硬卡**未分类 / 未声明 covers / 孤儿格 / 规则重叠 / 规格与实现漂移**；
- **规则数趋势是量化证据**：规则数↑ 而格子数不变 = **在打补丁（走错方向，退回重做）**；规则数持平、格子数↑ = 正常；规则数↓ = **真收敛**；
- 红线：**不得为了让工具通过而删维度或删坏法**——那是把逃逸面藏起来。

**② 提示词 / 规则类资产（无确定性检查器）** —— 枚举式清单对开放输入**天然不完备**（总会有没写到的输入）。根解不是"把清单写得更长"，而是**决策程序 + 兜底条款**：

- 任何输入先**归因到有限类**再处置；枚举表只作「程序已知实例」；
- 明写「**不存在『没写所以临场发挥』的状态**」——遇到未列出的输入，也走同一个归因程序；
- **终止判据 = 覆盖矩阵无空格**：把输入空间分解为有限维度（阶段 × 请求类型 × 信息完备度 × 输入性质 × 数字来源 × 多轮），**每格有规则即收敛**。

⚠️ 只对检查器讲收敛、对提示词不讲，是最常见的半拉子——**两类都要讲**。
