# 安装 ID 与精确名称手册（install-id-playbook）

> 用途：保证"给的 ID 用户一定能装上"。名字会撞车、会搜不到，ID 一锤定音。

## 三类资产，三种给法

### 1. 市场技能 → 给 `skill_xxx` 形式的安装 ID

- 唯一正确来源：技能市场检索工具返回的 `skillId`（如 `skill_2095914871509921792`）。
- **禁止**：凭记忆写 ID、自己拼 `skill_数字`、把别的技能的 ID 张冠李戴。
- 检索时同时记录：技能名、一句话说明、版本号，三样一起给用户。

### 2. 专家 → 给精确的市场卡片名

- 用户看到的是**市场卡片名**（`display_name_zh`），不是发布控制台的职业定位（`profession_zh`），
  两者常常不一致。推荐时一律用市场卡片名。
- 同名坑（真实案例）：「亲子沟通教练」在平台上有 2 个，分属两个不同作者。
  给专家名时如有同名风险，补一句"搜出来有两个同名，选头像是 XX 的那个"。
- 用户按名字搜不到 ≠ 不存在：客户端只在按调用量排序的前 2000 名里做本地过滤，
  长尾专家搜不到是常态，此时给分享链接或让用户从分类页翻。

### 3. 连接器 → 给精确名 + 授权入口

- 连接器名必须与连接器管理页显示名一致。
- 必须附授权指引（详见 connector-auth-guide.md）。

## 推荐话术模板

```
【结论】就选 XX（✅ 零安装 / ✅ 已装 / 🔌 已连接 / 🟡 需安装 / ⚠️ 需授权）
安装 ID：skill_xxxxxxxxxxxxx（技能）｜ 精确名：XX（专家/连接器）
【怎么装】客户端 → XX 页 → 搜索/粘贴 ID → 安装
【最小验证】装完后 30 秒做这件小事，确认能用：……
```

## 红线回顾

- ID 和名字**一个字都不能编**。检索不到就说"目前没有现成的"，给最接近的替代。
- 给过 ID 的推荐，宁可少给，不可错给——用户装不上一次，信任就没了。
