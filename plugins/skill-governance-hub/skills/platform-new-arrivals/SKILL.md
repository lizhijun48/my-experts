# platform-new-arrivals（新货周报）

把"用户每周手动找工具"变成"问一句就出盘点"。本技能定义取数口径、快慢双档、降级路径和产出格式。

## 触发词

新货、这周上了什么、周报、有什么新工具、最近上架、有什么值得装的。

## 取数（只信本地登录态，不掺外部搜索结果）

用 `scripts/pull_market.py`（随本技能附带）：

1. 抓令牌：从 `~/.workbuddy/logs/**/*.log` 抓 Bearer。
   ⚠️ 正则必须吃满 JWT 三段（含签名段），只匹配到第二段会拿到残缺令牌，所有接口 401。
2. 全量拉专家市场：`POST /v2/operation-platform/market/expert/list`，page_size=100 翻页到底。
3. 技能市场：用宿主的市场检索工具（action=search）按关键词查，记录返回的 `skillId`。

## 口径（数字必须可复核）

- `created_at` 是 UTC，**+8 转北京时间后**再按自然日过滤，取近 7 天。
- 调用量用 `use_count`（累计值，App 卡片同口径）。
- 官方活动投放型异常量（如外卖券类百万级）单独标注"疑似投放"，**不进推荐**。
- 产出物底部必须附「口径与方法说明」：数据源、时间戳处理、调用量口径、异常值剔除原因。

## 快慢双档（体验优先）

| 档位 | 什么时候用 | 怎么跑 |
|---|---|---|
| **快档（默认）** | 用户随口问"有什么新货" | ① 当天缓存快照存在 → 直接用；② 不存在 → 先跑一次慢档存缓存（首次约 1~2 分钟，**提前告知用户**），再出结果 |
| **慢档** | 用户明确说"做全量盘点/完整周报" | 全量拉取 + 完整分析，接受等待 |

缓存位置：`~/.workbuddy/cache/new-arrivals/snapshot-YYYY-MM-DD.json`，**当日有效，隔天作废**。
缓存里必须有拉取时间戳，引用时注明"数据截至 YYYY-MM-DD HH:MM"。

## 降级路径（取不到数时绝不编）

按顺序尝试，全部失败才走第 4 步：

1. 换更新的令牌重试一次（401 多为令牌过期）。
2. 读最近一次缓存快照（哪怕过期），**明确注明数据日期**。
3. 只用技能市场检索结果（它走宿主鉴权，通常不受影响）出一份"技能侧盘点"。
4. 如实告知："平台专家市场数据暂时取不到"，说明原因，请用户稍后再问。
   **任何情况下不得用记忆、推测或外部搜索结果填充平台数据。**

## 两档输出（面向所有用户，不含任何特定用户的个人画像）

- **通用档**（用户没说关注什么）：近 7 天新上架总数 → 调用量靠前的值得看 → 同赛道拥挤警示 → 值得装的 K 个（宁缺毋滥）。
- **定制档**（用户说了方向，如"我关心量化"）：按用户给的关键词筛，只留该方向，其余结构同上。
  ⚠️ 方向词来自用户当下这句话，不要预设任何默认方向。

## 产出格式

- HTML 周报（浅色卡片式，手机电脑都能看）或对话内 Markdown，按用户场景选。
- **结论前置**：开头 3 行内给本周结论，不甩清单让用户自己挑。
- 每个推荐：它是什么 → 为什么值得 → 精确安装 ID/名称 → 适合谁。
- 拥挤警示要具体：哪条赛道、一周冒出几个同质新品、为什么别挤。

## 红线（本技能特有）

- **绝不把令牌打印、回显或写进任何交付物**；日志路径只用于取数，不外泄内容。
- 脚本路径一律 `~` 动态展开，**不硬编码任何用户名**（本包面向所有用户）。
- 只推荐真实存在的条目，名称/ID 一个字不编造；检索不到就说没有。
- 调用量数字只能来自当次接口返回或标注了日期的缓存，禁止凭印象引用旧数字。
