# suite-dispatcher · 技能总调度

> 你的专属 Agent 统一入口：**说业务目标，不报技能名**。由业务流程驱动路由，按需读取 `~/.workbuddy/skills/` 下约 140 个自建技能并执行。

---

## 为什么要它

平台索引了你 191 条用户技能，但其中 **179 条 `disableModelInvocation: true`**——模型被禁止自动调用，只能你手动点名。191 个技能记不住，等于 AI 的路由价值被锁死。

本专家绕开这个锁，靠的不是打开开关，而是机制差异：

| 路径 | 是否受限 | 代价 |
|---|---|---|
| `Skill` 工具自动触发 | ❌ 被 `disableModelInvocation` 锁死 | 需逐个开白名单，且全开会导致上下文膨胀 |
| **`Read` 读 `SKILL.md` 全文** | ✅ 不受限 | 只读命中项，按需加载 |

所以它做到三零：**零开关、零复制、零改动现有技能**。

---

## 三级渐进加载（算力设计）

| 层 | 内容 | 何时读 | 成本 |
|---|---|---|---|
| L1 常驻 | 本插件提示词内的「路由总表」 | 永远在上下文 | 极低 |
| L2 按需 | `BUSINESS-FLOW-MAP.md` 具体流程步骤 | 需要精确步骤/多技能链时 | 中 |
| L3 按需 | 命中的 1–3 个 `SKILL.md` | 执行前读一次 | 高（只读命中项） |

硬纪律：**一次任务最多加载 3 个技能**，超过就拆任务。

---

## 它继承的既有资产（不新建平行体系）

- **路由表** = `~/.workbuddy/skills/BUSINESS-FLOW-MAP.md`（v1.3.0，业务→技能唯一映射）
- **入口壳模式** = `pm-suite/pm-product-expert`（JT-021）：接单后路由、不重复实现
- **技能本体** = `~/.workbuddy/skills/<suite>/<skill>/SKILL.md`（单一事实来源，不复制）

---

## 路由回执（自检机制）

每次回答第一行给：

```
🧭 路由：JT-FLOW-001 步骤5「采购与质量规划」｜加载：pm-procurement-quality (JT-008)
```

挑错了你一句话纠偏，它立刻换技能重做。

## 目录结构

```
.codebuddy-plugin/plugin.json     # 注册（expertType=agent，未挂 skills —— 有意为之）
agents/suite-dispatcher.md        # 调度器提示词（L1 路由总表 + 三级加载 + 八条纪律）
avatars/expert.png                # 头像
README.md                         # 本文件
```

> **为什么 `plugin.json` 不挂 `skills`**：一挂就要把技能目录复制进插件，会产生 140 份副本，违反「融合不建平行」，且改一处要改两处。本专家靠 `Read` 读单一事实来源，故不挂。
